# Reference System Structure Guide

This file defines the organizational rules for all manifest files in `/docs/reference/`.

---

##  Folder Categories

Each subfolder groups real-world reference manifests by primary system use:

- `physics/`  Material behavior, biological structure, planetary systems, quantum mechanics
- `visuals/`  Symbolism, color logic, typography, procedural aesthetics
- `audio/`  Music theory, cultural instruments, procedural synthesis
- `ai/`  Behavioral psychology, tribal logic, emotion response, enemy decision-making
- `entropy/`  Thermodynamics, chaos theory, entropy weighting, quantum collapse overlays
- `history/`  Historical timelines, territorial conflict, factional events, crusades
- `lore/`  Mythology, religious cosmology, scriptural structures, belief systems

Codex is permitted to create new folders and manifest domains as needed to support future systems.

---

##  Multi-Domain Usage

> Some manifest files appear in multiple folders. This is **intentional**.

Each instance is treated as a valid reference for its domain. Do not attempt to deduplicate unless the content is being rewritten to match a new system purpose.

Codex must treat each file path as valid and independent.

---

##  Manifest Format

Each manifest follows this structure:
- **Name**  of the source
- **Type**  e.g., paper, dataset, textbook
- **URL**  direct, working link
- **Use**  how Codex should apply it in that domain

---

##  Codex Usage Rules

- Check for relevant manifests before inventing simulation logic
- Use manifest data when available  do not hallucinate
- Do not attempt to merge duplicate manifests unless directed
- Codex is encouraged to propose new manifests if no reference exists
- Codex must never overwrite quantum engine systems  `[REDACTED]` is interpretive only
