Bootstrap Recovery, Day 7 Codex Self-Heal

Day 7 taught us that stability isn’t just about rendering a frame—it’s about keeping Codex’s own tools from sabotaging the run. The engine stalled at the title screen, container builds refused to resolve GLFW, and the studio needed a trustworthy rollback point. We captured every misfire in the Devlog Vault and forced the agent to heal its environment so the next sprint isn’t held hostage by bootstrap drift.

Evidence chain

All of today’s recoveries are logged in the Devlog Vault. Input sequencing, the V0.1 branch snapshot, and the GLFW vendor mandate each include timestamps, log excerpts, and the policy locks that keep the fixes in place for future audits.

The input deadlock we deserved

We opened Day 7 to a frozen build. Gameplay scaffolding was solid, but the first Enter press never landed because InputManager::Update() ran after glfwPollEvents(). The state snapshot cleared before we ever read it, which meant GameManager never left the menu. Codex caught the regression, reordered the polling, and proved the fix by logging the engine boot, Game::StartGame(), and the transition into Playing in the same second. (Master Devlog · 2025-06-14)

With the input loop corrected, we pulled the multi-scene streamer into the runtime so transitions finally flow without manual scene pops. It’s the first time the new queue has run under live input, and it sets up the cross-window choreography we’ll need for debug overlays. (Engine Devlog · 2025-06-14)

Locking a rollback point we could trust

With the menu flowing again, we froze a clean checkpoint. Codex tagged the V0.1 branch the moment the input logs showed Game::StartGame() landing, giving us a permanent “first kernel complete” baseline if future experiments go sideways. (Master Devlog · 2025-06-14)

Vendor lock as a survival strategy

Fixing gameplay revealed a deeper threat: Codex containers can’t see GLFW, Wayland, or X11 headers. Every bootstrap attempt died before linking, and there’s no persistent package cache inside the agent sandboxes. The only escape was to hard-vendor GLFW, rip out FetchContent, and wire add_subdirectory(deps/glfw) straight into CMake. (Master Devlog · 2025-06-14)

The policy update codifies what the audit uncovered: submodules are banned, dependencies live in-repo, and Codex bootstrap relies exclusively on scripted package lists. Anything else leaves the agent blind the next time a container resets. (Master Devlog · 2025-06-14)

Mandating the bare-metal headers

Vendoring solved GLFW discovery, but Codex still needed the underlying GL toolchain. The same audit locked scripts/setup.sh to install build-essential, cmake, ninja, and the mesa headers every run so link failures stop hiding behind missing packages. It’s the minimum bootstrap the containers can rely on, and the Devlog spells out the exact command list the studio adopted. (Master Devlog · 2025-06-14)

Day 7 closed with Codex’s input loop restored, a fallback branch archived, and the container bootstrap hardened enough to survive a full reset. Tomorrow’s work can chase OpenGL vendor experiments knowing the baseline won’t collapse again.
