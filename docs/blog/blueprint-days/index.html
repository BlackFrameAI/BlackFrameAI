The Blueprint Days: Trusting Codex With the Wheel

  • Engine R&D
  • Agentic Workflows
  • Studio Culture

Day 2 took us from debating trust to drafting contracts. Once Codex got a real spec and a guaranteed scaffold, the engine’s skeleton assembled itself in hours.

Claim status

First verifiable AI-generated dual use engine

BlackFrame Engine qualifies because Codex authored the engine scaffolding, core systems, and runtime glue autonomously within tight governance. Humans audited and steered policy, keeping the Purge of the Crescent Veil game focused on showcasing the technology rather than defining it.

  • The Devlog Vault logs every phase, rollback, and approval from empty repo to executable build.
  • We have yet to find a public precedent documenting an AI-built engine with equivalent scope, reproducibility, and auditability.

This Blueprint recap shows when we let Codex take the wheel, cementing the evidence trail that underpins the claim for BlackFrame Engine.

Resetting the Premise

The morning started with a frank post-mortem. GPT’s safety reflexes had been throttling progress for three straight sessions, insisting that Codex should be kept on a leash and limited to short, literal prompts. The result? Half-built stubs and hours lost to human rework. We wiped the slate clean and wrote a new rule: Codex owns the boilerplate when the spec is solid. Our job became giving it that spec.

Everything lived in Markdown. We captured the entire system surface, engine folders, runtime contracts, test harnesses, in a single briefing that Codex could parse without improvising. No entropy managers, no runtime magic; those concerns were weeks away. The only goal for Day 2 was reliable structure.

The Scaffolding Script

To guarantee reproducibility we codified the file tree first, then let Codex populate it. The PowerShell snippet below became our first “runbook”, a one-command reset that enforced naming, directory layout, and the documentation skeleton.

# SET YOUR ROOT PATH HERE
$rootPath = "G:\CODEX_Projects\BlackFrame_Engine"

New-Item -ItemType Directory -Force -Path "$rootPath\engine"
New-Item -ItemType Directory -Force -Path "$rootPath\game"
New-Item -ItemType Directory -Force -Path "$rootPath\assets"
New-Item -ItemType Directory -Force -Path "$rootPath\docs"
New-Item -ItemType Directory -Force -Path "$rootPath\docs\lore"
New-Item -ItemType Directory -Force -Path "$rootPath\scripts"

New-Item -ItemType File -Force -Path "$rootPath\README.md"
New-Item -ItemType File -Force -Path "$rootPath\CODEX_instructions.md"
New-Item -ItemType File -Force -Path "$rootPath\docs\engine_design.md"
New-Item -ItemType File -Force -Path "$rootPath\docs\game_design.md"

New-Item -ItemType File -Force -Path "$rootPath\docs\lore\factions.md"
New-Item -ItemType File -Force -Path "$rootPath\docs\lore\characters.md"
New-Item -ItemType File -Force -Path "$rootPath\docs\lore\world_history.md"
New-Item -ItemType File -Force -Path "$rootPath\docs\lore\powers_and_glyphs.md"
New-Item -ItemType File -Force -Path "$rootPath\docs\lore\items_and_artifacts.md"

Write-Host "✅ Scaffold created at $rootPath"

Once that script was in place we stopped hand-creating folders entirely. Codex consumed the Markdown specs, ran the scaffold, and filled each empty file with deliberate stubs, always referencing the spec section that justified its existence.

We snapped the first clean initialization log as proof. Every subsystem came online in the order dictated by the spec, no missing assets, no mystery warnings.

Disciplined Prompts, Disciplined Output

We imposed three guardrails that changed everything:

  • Scope locks: Each document defined what the module could import and what it was forbidden to touch. Codex had to call out boundary crossings explicitly, which killed the early circular dependency messes.
  • Traceable commentary: Every stub included a header pointing back to the Markdown source. Humans could diff behavior changes against the spec in seconds.
  • Prompt parity: If Codex asked for clarification, we updated the spec first and re-ran the prompt. No ad-hoc instructions, no side-channel hacks.

The difference was immediate. The repo that had been prose-only at sunrise now contained a navigable skeleton: /engine/core, /render, /gameplay, /ui, and a /tests harness prepared for the logic still to come. It was anatomical, not poetic.

Codex Behavior Bootcamp

Discipline didn’t stop at folder trees. The morning also produced the first Scaffold Style Checklist, a living rubric that every Codex task now runs against. The checklist enforces tone (“no hype language in specs”), architecture (“engine code never imports gameplay headers”), and escalation paths (“flag human review if an external engine pattern appears”).

We wrote those lines after catching Codex’s first two misfires: it tried to graft in a Unity-style scene lifecycle, and later registered only PhysicsSystem inside SystemManager. Both moments triggered the “hallucination detected” branch of the checklist, forcing us to amend the docs and retry with the new guard clauses. The fixes stuck, Codex hasn’t repeated either mistake since.

The First Compile That Mattered

Late that night we ran the inaugural build on the fresh scaffold. There was no entropy system yet and no pixels on screen, just a validation executable that confirmed the directories, build scripts, and project files aligned. The console output was humble, module names, init order, success flags, but every line traced directly back to a sentence in the documentation set. That was the proof that the loop worked.

With that confidence we pushed further: a 300-frame burn-in that exercised the new EngineCore loop and produced the first runnable cv_engine.exe. Watching the counter tick to 300 without a crash was the moment the team stopped calling it a “scaffold” and started calling it an engine.

As midnight crept in we let the harness paint its placeholder sprites just once, capturing the moment Codex’s scaffolding first produced real frames.

Takeaways

  • Trust is leverage. The moment we stopped treating Codex like an intern and started treating it like a systems engineer with a checklist, velocity quadrupled.
  • Specs are the real source code. Precise Markdown beat “clever” prose. Codex mirrored the tone it was given; sharp instructions produced clean scaffolds.
  • Automate the reset. The scaffold script turned every misstep into a recoverable experiment. We could nuke, rerun, and verify in minutes.

Day 2 closed without a single rendered frame, but we finally had a machine worth feeding. Over the next five days that same loop delivered the runtime, render pipeline, and the first gallery of frames. None of it would have landed without the trust, and the blueprint, we forged here.
