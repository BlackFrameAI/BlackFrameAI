Game Takes the Stage — Day 3 Runtime Merge

January 19, 2025 — Written by BlackFrame AI Studio

The third day of the Crescent Veil push was about commitment. The scaffolding Codex raised over the past two dispatches worked, but it still booted through a toy harness. Today we deleted the training wheels, pointed every executable at the real game::Game runtime, and proved that the multi-window debug view can render the live procedural sprite stack without guard clauses.

Morning — Retiring the Minimal Harness

We started the day by ripping out MinimalGame everywhere it still lingered. The runtime target no longer compiles the minimal sources, every launcher that previously toggled --minimal now instantiates the full game class, and the backend validation sample boots the same stack that ships in production builds. GameManager follows suit, pushing the complete scene progression regardless of build flags so that Play always transitions into the full placeholder loop.

“Removed MinimalGame as a test harness. The real Game class is now always used for engine initialization.”

Removing the switch wasn’t cosmetic; it tightened the safety net. Without a fallback scene, checkpoint callbacks, telemetry hooks, and save setup are exercised every time we launch, which is precisely what the Phase 5 runtime loop needs. Documentation and the modular system tree were updated immediately so the source of truth now lists Game as the sole implementation behind IGame, and the dedicated minimal-game page was deleted to avoid drift.

Midday — Debug Windows Show the Real Sprite Stack

Once every entry point was pointed at the full runtime, we tightened the render loop. All four validation scenes and the debug overlay window now call into ProceduralSpriteManager directly instead of tiptoeing through null checks. The result is a clean sequence: bind UI state, hand the draw pass to the sprite manager, then let the vector font layer over the top. The change pairs with last night’s guard-rail work in the game devlog where we removed null checks from Game and asserted that the sprite manager must exist before rendering.

That confidence let us keep the diagnostics overlays active even when bouncing between windows. The debug viewport pulls the same sprite grid as the primary display, logs its projection matrices, and continues to host the ASCII diagnostics grid without duplicating setup code.

Below is the first capture after the switch — the Crescent Veil runtime waking inside its new multi-window layout without the minimal harness to protect it.

Afternoon — Documenting the New Default

To close the loop we cleaned up the paperwork. The game flow documentation no longer references a “minimal mode” fast path; every mention of MinimalGame was removed from the modular tree, and the deleted system file was struck from the docs entirely. That paperwork might feel mundane, but it guards the contract we set on Day 1: if it isn’t in the docs, it doesn’t exist. Day 3 ends with the runtime, the launchers, and the docs all describing the same engine.
