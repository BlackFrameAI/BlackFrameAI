First Light, Day 5 Render Bring-Up

Day 5 was our first real attempt to let Codex draw something. The telemetry loop held steady yesterday; today we pushed the OpenGL backend, window stack, and render facade into the same lane so the next sprint can ship visible frames without rewriting the engine.

Evidence chain

Every statement below is backed by the Devlog Vault. We cite the exact documents and raw build logs that walked the renderer online so partners can audit the trail without leaving our ecosystem.

Standing on yesterday’s instrumentation

Day 4 locked EngineController, TickTimer, and the LogChannel telemetry spine into a deterministic cadence. Those entries are why we could flip from simulated ticks to real GPU work without losing observability—LogChannel already fans RendererFacade, ResourceLoader, InputRouter, and SceneDirector into a shared telemetry stream at 60 Hz. (Engine Devlog · lines 1574–1577)

The game layer stayed in sync. Before we touched the renderer, the gameplay devlog verified that the scene handshake still promotes through EngineController so today’s render pass could slot in without rethreading GameManager. (Game Devlog · lines 755–757)

Wiring the window stack to real OpenGL

We hard-wired MultiDisplayManager, InputBroker, and RenderSystem to the primary GLFW window, forcing a context check and OpenGL 4.5 verification before the first frame. Codex now stores a window context shim on the user pointer, registers resize callbacks, and spins GameManager with the real renderer instead of the minimal stub, pushing Scene0 straight onto the live scene stack. (Day 5 render notes · lines 9–10)

The rest of the engine benefits from that swap: VectorFont boots before scenes mount, debug overlays only instantiate when additional bindings exist, and checkpoint callbacks now ride the same RenderSystem that will draw the run. (Day 5 render notes · line 11)

Toolchain grind: getting GLAD, GLFW, and friends across the line

Bringing first light meant pushing the entire vendor toolchain through our container build. GLAD regenerated the OpenGL 4.5 loader, OpenAL Soft and libcurl rebuilt under the tightened warnings, and the compile log shows Codex chewing through 884 targets before the renderer headers tripped the first failure. (Build log · lines 1–120)

The failures were exactly the kind we want at this stage: BackgroundRenderer pulled `RenderSystem::BatchVertex` before the forward declaration was complete, blocking the link. That’s the spot where Codex will refactor include boundaries tomorrow; today we proved the pipeline, dependency graph, and build commands all fire together.

The guardrails we leaned on

This bring-up works because the engine documentation already mandates that every visual—UI, gameplay, debug overlays—travels through RenderSystem’s batched OpenGL path. SharedGLResourceFactory guards GL context usage, procedural fonts auto-load, and scenes validate ImGui and OpenGL contexts before rendering. The renderer is never raw OpenGL calls anymore; the docs lock that policy down. (Engine docs README · lines 11–27; lines 33–34)

Even shutdown is scripted. Prior sprints added headless tests and teardown order checks so ImGui contexts, shared GL resources, and window bindings unwind safely—a prerequisite when you start toggling real windows mid-loop. (Engine Devlog · lines 1560–1569)

What’s next

Tomorrow is about clearing the include guard snag, letting RendererFacade talk to real math backends, and proving a frame. With the telemetry spine already tapping RendererFacade and the gameplay handshake intact, Codex can focus purely on rendering correctness rather than plumbing. (Engine Devlog · lines 1574–1577; Game Devlog · lines 755–757)

Day 5 closed with the lights almost on. The next run should finally show what Codex has been painting in telemetry.
